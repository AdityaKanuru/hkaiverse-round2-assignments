## Project idea
**SkillBridge CSE** connects each curriculum recommendation to a demonstrable student skill and an assessment artifact. Instead of adding trendy subjects without a plan, it asks: *What should a graduate be able to show, how will the course teach it, and what evidence proves learning?*

Example: a web/API learning outcome should produce a working API, tests, readable documentation and a short security checklist—not only a theory exam.

## Method
1. Use public IFHE pages as primary institutional sources.
2. Compare course themes with three or more public job descriptions accessed on 24 Oct 2026.
3. Separate foundational courses from applied practice and fast-changing tools.
4. Keep the core intact; propose targeted updates and a limited practical module rather than wholesale credit replacement.
5. Record AI-assisted review exercises with a human-check field; AI suggestions are not treated as facts.
6. Use the included HTML calculator to change the assumptions and see the total proposed credit delta.

## Key findings
- Core foundations such as data structures, algorithms, operating systems, databases, discrete mathematics, and programming remain important.
- Job descriptions increasingly mention practical software engineering alongside AI: APIs, full-stack integration, RAG/LLM concepts, testing, security, governance, and production support.
- A course title alone does not show whether its teaching or assessment is current. The recommendation is to update learning outcomes, labs, and assessment evidence before adding many new courses.
- The most practical change is a small, prerequisite-aware **AI Workflow and Responsible Automation Lab** with a capstone that builds on programming, databases, web technologies, and software engineering.

## Recommended actions
- **KEEP:** core programming, data structures/algorithms, databases, operating systems, discrete mathematics, theory of computation, computer architecture and networks.
- **UPDATE:** software engineering, web technologies, database labs, project work and assessment rubrics to include APIs, tests, version control, accessibility, security and documentation.
- **REDUCE:** duplicated lecture-only coverage where a topic is already assessed elsewhere; reduce only after mapping learning outcomes, not by deleting essential content.
- **ADD (proposed):** small-credit AI workflow lab with source-grounded retrieval, evaluation, privacy, human approval and failure handling. This is a proposal subject to academic approval and total-credit/prerequisite constraints.

## SkillBridge outcome-to-evidence examples
| Skill area | Student evidence | Suggested assessment |
|---|---|---|
| Programming and problem solving | Readable code plus test cases | Code walkthrough and unit tests |
| Databases | Schema, sample queries and validation | Query task with edge cases |
| Web/API integration | Small client-server feature | API tests, error handling and README |
| AI-assisted workflow | Synthetic-case workflow with approval boundary | Test normal and failure cases; explain where human review is required |
| Responsible computing | Privacy and security checklist | Scenario-based review and reflection |

These are proposed assessment examples. Faculty should map them to the official course learning outcomes and batch regulation before implementation.
